What these files are

server_keys/private.key
The 32-byte static server private key. Your Jade is configured to trust the public key derived from it, and your PIN records are encrypted with a key derived from it. Lose this and PIN unlock stops working permanently.
server_keys/public.key
Derived from the private key, so it needs no separate backup. This is what the Oracle QR code encodes.
pins/*.pin
The encrypted PIN records — one per wallet. This is what actually releases the wallet key when you enter the correct PIN. Both the private key and the matching .pin file are required. Neither alone is enough.

Backing up

Copy the whole data directory somewhere safe, ideally to encrypted offline media.

Treat this backup like a wallet backup. Anyone holding both the backup and your Jade gets unlimited PIN attempts, because restoring the files also restores the three-strikes counter. Keep it encrypted, and keep it off any networked machine.
Keep this out of cloud sync and automatic backups.

The default data directory sits inside a folder that consumer backup and sync tools capture by default. Your server private key is the secret that guards PIN access to your wallet — sending a copy to a third-party server quietly undoes the point of running an air-gapped oracle.

Check specifically for:

  • macOS — Time Machine backs up ~/Library/Application Support. Exclude this folder under System Settings → General → Time Machine → Options.
  • iCloud Drive — if Desktop & Documents syncing is on, keep backups out of those two folders.
  • Google Drive, Dropbox, OneDrive — never place a backup inside a synced folder. These upload silently and retain deleted-file history.
  • Windows — OneDrive folder redirection often captures %APPDATA%-adjacent user folders. Verify before trusting it.

Prefer an encrypted USB drive or other offline media that never touches a networked machine.

This backup is not a wallet backup. It restores PIN unlock only. If you lose it, your funds are still recoverable from your BIP39 recovery phrase — that phrase remains the thing you must never lose.

Restoring onto a new machine

Use this when moving an already-configured Jade to a fresh install — do not re-scan the Oracle QR, which would require a factory reset.

  1. Quit this application completely.
  2. Copy your backed-up server_keys/ and pins/ folders into the data directory shown above, replacing anything generated there.
  3. Start the application again.
  4. Return to this page and confirm the server public key matches the one your Jade was configured with.
Alternative — run against a backup in place
SimpleJadePinServer --data-dir /path/to/your/backup
Upgrading from the original script? If a key_data/ folder from the upstream SimpleJadePinServer is found next to the app or in the working directory, it is imported automatically on first run and the original is left untouched as a backup.
